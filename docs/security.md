# Security and performance

The public MVP exposes read-only catalogue endpoints and bounded report generation. There are no user accounts or private per-user datasets. Deploy private datasets behind an authenticated gateway; multi-tenant access control is not implemented.

Live ingestion is disabled by default. Enabling requires a server-only, randomly generated operator token of at least 32 characters. Spotify additionally requires server-only client credentials; MusicBrainz requires an identifying User-Agent only for its own importer. Send the token as an Authorization Bearer header only to the ingestion endpoint over HTTPS. It is never placed in a browser environment variable. Rotate it through the hosting secret store. API authorization compares tokens in constant time. Global PostgreSQL advisory locks serialize ingestion across workers, and a durable 60-second cooldown limits new runs. Every MusicBrainz request waits at least 1.05 seconds, including retries. A MusicBrainz run imports at most MUSICBRAINZ_MAX_RELEASES (default 20, maximum 100) official release editions.

PostgreSQL is bound to loopback in development. Use managed encrypted PostgreSQL in deployment; change local defaults. CORS and accepted Host headers are explicit lists. JSON writes are limited to 8 KiB, including streamed bodies. Error responses omit database/credential details. Logs include generated request IDs, method, path, status and duration, excluding query strings, bodies and auth headers. Keep proxy access logs configured to omit credentials.

Search treats `%` and `_` literally and uses bound SQL parameters. Pagination is bounded to 100 results. Artist serialization batch-loads relations, sources, snapshots and track counts; a regression test enforces a constant query budget as page size grows. Analytics aggregate in PostgreSQL before pandas processing. CSV export escapes spreadsheet formula prefixes. PDF strings are escaped, output is generated in memory, report sizes are bounded, and an advisory lock permits only one concurrent report across workers. No third-party arbitrary URLs are fetched.

For an Internet-facing launch, use TLS, automated database backups, monitoring and an ingress/gateway rate limit (including report POST requests and request/read timeouts). The application deliberately avoids an in-process IP limiter, which would be unreliable behind multiple proxies/workers. Performance tests establish query behavior on fixtures, not Internet-scale load capacity. No blanket security certification or load-test claim is made.

Spotify client secrets use redacted settings, are sent only to the fixed token endpoint, and never appear in browser bundles or API responses. Access tokens stay in process memory and are refreshed on expiry/one 401. Spotify requests use fixed endpoints plus validated 22-character IDs, do not follow redirects/pagination URLs, bound page sizes/import scope and propagate rate limits. Client Credentials grant no user-library/playback access. The import helper refuses redirects to prevent forwarding the operator token. See spotify.md for app setup and current access/terms requirements.
